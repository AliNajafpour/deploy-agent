# وضعیت پروژه برای ارائه

این ارزیابی بر اساس متن [چالش](../challange.md) و توضیح داور دربارهٔ امکان اصلاح
کد بک‌اند تهیه شده است. ویدئوی معرفی چالش در دسترس نبود؛ ویدئوی دموی خود پروژه
طبق تصمیم صاحب پروژه بعداً ضبط می‌شود. نمره یا سازگاری با حساب زندهٔ لیارا از
آزمون محلی نتیجه گرفته نمی‌شود.

## تطبیق با خواسته‌های چالش

| خواسته | پیاده‌سازی و شواهد | حدود |
| --- | --- | --- |
| اولین دیپلوی | ZIP، تشخیص نوع برنامه و پورت، بستهٔ ثابت، ساخت برنامه، آپلود، release و بررسی سلامت؛ `service.py` و `test_workflow.py` | پلن واقعی و قیمت را اپراتور تنظیم می‌کند؛ قیمت حدس زده نمی‌شود |
| اطلاعات ضروری کاربر | تشخیص نام تنظیمات از env و کد، فرم کلید و اتصال دیتابیس، ذخیرهٔ رمز‌شده؛ `test_inputs.py` و `test_uploads.py` | اتصال دیتابیس موجود؛ ساخت خودکار دیتابیس ابری پیاده نشده است |
| عملیات لیارا | API تایپ‌شده برای لاگ، رویداد، منابع، env، ری‌استارت، منابع، دامنه، DNS و SSL؛ قراردادهای [API](reference/README.md) | انتشار و عملیات حساب زنده در این تحویل آزمایش نشده‌اند |
| تشخیص و رفع خطا | جمع‌آوری شواهد، فرضیه و اطلاعات کم‌شده، اصلاح محدود فایل‌های موجود بک‌اند، diff، تأیید و بررسی نسخهٔ دقیق؛ `test_backend_repair.py` | نحو و حدود تغییر بررسی می‌شود؛ درستی معنایی هر patch نیازمند بازبینی و بررسی نتیجه است |
| پایش مستمر | فعال‌سازی برای هر سایت، تنظیمات پایدار، بررسی هر دقیقه، رخداد پس از دو شکست، تحلیل یک‌باره و بستن رخداد پس از بازیابی؛ `test_monitoring.py` | دادهٔ ناموجود نامعلوم می‌ماند؛ پایش خودش اقدامی را تأیید نمی‌کند |
| تجربهٔ ساده | ZIP و درخواست عادی، فرم اطلاعات ضروری، پیشنهاد کوتاه، دکمهٔ تأیید در بالای کادر، جزئیات بسته و طراحی فارسی مطابق جهت بصری لیارا؛ `test_ui.cjs` | یک اپراتور؛ حساب مستقل برای کاربران عمومی ندارد |
| تأیید و پایداری | digest طرح و هش سورس، دفتر اقدامات، checkpoint، جلوگیری از تکرار نتیجهٔ نامشخص؛ `test_workflow.py` و `test_safety.py` | یک پردازش و یک نمونهٔ فعال؛ checkpoint تراکنش ابری را اتمی نمی‌کند |
| اجرای خود دستیار روی لیارا | Dockerfile، پورت 8080، دیسک `/data`، GitHub یا CLI و doctor آفلاین؛ [راهنمای فرمان‌ها](cli-setup.md) | کلیدها، برنامه و دیسک باید در حساب میزبان آماده شوند |
| تحویل مستندات | [README](../README.md)، [معماری](design.md)، [میزبانی](liara-hosting-research.md)، [محدودیت اصلاح](deployment-repair.md) و این سند | ویدئوی حدود پنج دقیقه بعداً ضبط می‌شود و طبق چالش برای ارسال نهایی الزامی است |

## ویژگی‌های برگرفته از تحقیق جهانی

[تحقیق مقایسه‌ای](research-global.md) منابع اولیه و حدود هر نمونه را ثبت می‌کند.
این‌ها در پروژه به شکل عملی استفاده شده‌اند:

- تأیید برای عملیات و پارامترهای دقیق، با الهام از AWS DevOps Agent و Pulumi Neo.
- جداکردن «درخواست پذیرفته شد»، «نسخه آماده شد» و «سایت سالم است»، مشابه الگوی Railway و HolmesGPT.
- شواهد دارای شناسه، فرضیه‌های قابل بررسی و اعلام اطلاعات کم‌شده، برگرفته از incident.io و Rootly.
- هستهٔ مشترک برای API، Codex، Claude Code و MCP، با الگوی جداسازی مدل از ابزار در kagent.
- رخدادهای پایدار، تحلیل بدون تکرار و رفع خطای پیشنهادی با تأیید انسان، به‌جای ری‌استارت بی‌دلیل.

عمداً Kubernetes، ابزار shell عمومی یا چارچوب جدیدی به پروژه اضافه نشده است.
برای این MVP، APIهای محدود و همان FastAPI، LangGraph و SQLite مسیرهای لازم را پوشش می‌دهند.

## نتیجهٔ آزمون این تحویل

در ۲۰۲۶/۱۰/۲۳، مجموعهٔ Python شامل ۱۸۱ تست، آزمون رابط با Node و ساخت wheel
گذشتند. فایل‌های پایش و doctor، رابط و فونت در wheel بررسی شدند.
بازبینی مستقل سه ایراد یافت و اصلاح شد: تشخیص قطعی اتصال HTTPS، حفظ ارتباط سورس
با نسخه پس از بیش از ۵۰ عملیات، و patch فایل‌های بدون newline پایانی.
آزمون‌های رگرسیون برای هر سه وجود دارند. کندی شدید پوشاندن متن‌های محرمانهٔ بلند
نیز در تابع مشترک اصلاح شد.

فقط دو سناریو با مدل واقعی BoxAPI و `openai/gpt-6-luna` اجرا شدند:

| سناریو | نتیجه |
| --- | --- |
| ساده: انتشار سایت استاتیک | طرح قابل تأیید، نبود تغییر پیش از تأیید، انتشار و پاسخ HTTP واقعی محلی |
| سخت: خطای HTTP 500 در handler داخلی بک‌اند | اصلاح تقسیم بر صفر؛ پاسخ 200؛ میانگین `[]` برابر 0، `[2,4]` برابر 3 و `[0]` برابر 0؛ هش بستهٔ آپلودشده همان هش تأییدشده و سورس اصلی دست‌نخورده |

APIهای ابری در هر دو سناریو شبیه‌سازی شدند. تست سخت فقط fixture ثابت و محدودشده
با AST را اجرا می‌کند؛ سرویس اصلی هیچ کد دلخواه کاربر یا hook نصب را اجرا نمی‌کند.
خلاصهٔ ماشینی در [competition-verification.json](competition-verification.json) است.

در مرورگر، روشن‌کردن پایش و بازکردن پیشنهاد رخداد با دادهٔ جداگانهٔ آزمون بررسی شد.
این داده وارد تاریخچهٔ رابط اصلی نمی‌شود. [تصویر رابط پایش](monitoring-interface.png).

## کارهای خارج از کد

برای استفادهٔ ابری، اپراتور باید برنامهٔ Docker و دیسک `data` بسازد، کلید BoxAPI،
توکن زیرساخت لیارا، کد ورود مستقل، hostname عمومی و گزینه‌های واقعی میزبانی را
در پنل تنظیم کند. یک نمونهٔ فعال نگه دارد و کل پوشهٔ `/data` را پایدار و خصوصی
نگه دارد. [مراحل دقیق](liara-hosting-research.md).

`python -m lyara doctor --production` تنظیمات محلی را بدون تماس با مدل یا حساب
بررسی می‌کند؛ اعتبار کلید، DNS، TLS، mount واقعی و قیمت را ثابت نمی‌کند.
در محیط توسعهٔ فعلی، تنظیمات حساب میزبانی و ورود عمومی هنوز خالی‌اند.
این‌ها مانع انتشار واقعی‌اند و برای آزمون محلی لازم نیستند.

سپس ویدئو ضبط شود. ارائهٔ خروجی، تأیید انسان و نتیجهٔ قبل و بعد از اصلاح اهمیت
دارد؛ [سناریوی ویدئو](demo-script.md) آماده است.
