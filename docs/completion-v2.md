# رفتار نسخهٔ تکمیل‌شده

این نسخه روی هستهٔ قبلی ساخته شده است. [چالش](../challange.md)، مسیر واقعی وب/CLI/MCP
و [تحقیق قراردادهای رسمی و پروژهٔ مرجع](liara-api-completion-research.md) مبنای کارند.
سورس مرجع صرفاً منبع ایده بود؛ فرض‌های آن دربارهٔ 4xx، نشت حافظه، موجودی صفر،
تکرار نوشتن و جایگزینی ارائه‌دهنده منتقل نشده‌اند. ویدئو خارج از این مرحله است.

## بررسی سایت، با درخواست محدود

کشف مسیر، اجرای برنامه نیست. Python با AST و JavaScript با زیرمجموعهٔ محدود و
محافظه‌کارانه خوانده می‌شوند. نوشتن آشکار، helper ناشناخته، تغییر شمارنده،
عملیات خرید/حذف/ارسال، مسیر پویا، query و redirect خودکار کنار گذاشته می‌شوند.
مسیر `/` هم شاهد می‌خواهد. بدون مسیر قابل قبول، آماده‌سازی، بررسی و پایش تولیدی
به سایت درخواست نمی‌فرستند و نتیجه نامعلوم می‌ماند. مسیرهای یک سایت مدیریت‌شده
از بستهٔ ثبت‌شدهٔ release فعال انتخاب می‌شوند؛ سورس صریح کاربر مسیر جایگزین بررسی است.

این تحلیل محدود، رفتار پویا یا side effect پنهان هر وب‌سایت را اثبات نمی‌کند و ممکن
است مسیر معتبر را کنار بگذارد. تنها GETهای انتخاب‌شده بررسی می‌شوند؛ آزمون عمومی
POST، خرید، حذف و mutation نداریم. transport آزمایشگاه محلی یک مرز صریح آزمون است؛
تست سخت فقط fixture ثابت و محدودشده با AST را برای بازتولید خطای بک‌اند اجرا می‌کند.

بررسی قبل و بعد حداکثر سه نمونه برای هر مسیر دارد. تأیید پس از release شامل سه
دور با فاصلهٔ دو ثانیه و مهلت ۴۵ ثانیه است؛ transportهای صریح آزمون فاصله را صفر
می‌کنند. مقصد عمومی HTTPS با IP بررسی‌شده، Host/SNI درست، بدون کلید زیرساخت و
بدون redirect درخواست می‌شود. مهلت درخواست به زمان باقی‌مانده محدود می‌شود؛ DNS و
رفتار شبکهٔ سیستم‌عامل نیز روی زمان پایان اثر دارند. latency زمان دریافت هدر است،
نه رندر مرورگر. «رفع شد» فقط با خطای قبلی، پاسخ‌های فعلی مطابق انتظار و نسخهٔ پایدار
همان عملیات صادر می‌شود؛ کمبود شواهد نتیجهٔ قطعی نمی‌سازد.

## محاسبات پایش

خط مبنا حداقل پنج بررسی سالم در بازهٔ حداقل ۲۴۰ ثانیه می‌خواهد. آستانهٔ کندی
بزرگ‌ترِ دو برابر میانهٔ خط مبنا و ۱۰۰۰ms است؛ سه بررسی پیاپی لازم است. خط مبنا
در رخداد کندی یا فشار منابع از دادهٔ خراب یاد نمی‌گیرد. تاریخچه حداکثر ۱۲۰ نمونه
و ۲۴ ساعت است. وقفهٔ بیش از سه فاصلهٔ بررسی، شمارش متوالی را از نو شروع می‌کند.

برای منابع، حداقل پنج نقطه در حداقل ۶۰ ثانیه و تازه‌بودن در ۳۰۰ ثانیه لازم است.
فشار فقط با واحد و ظرفیت مشخص و سه نقطهٔ اخیر بالای ۹۰٪ ظرفیت تشخیص داده می‌شود.
یک پنجرهٔ متریک دوباره شمرده نمی‌شود. سه بررسی مستقل برای بازکردن رخداد فشار لازم
است. کندی و فشار با دو بررسی تازهٔ عادی بازیابی می‌شوند؛ قطعی با یک پاسخ HTTPS
موفق بسته می‌شود. دادهٔ گمشده هیچ علت بازی را حل‌شده نمی‌کند.

قرارداد عمومی metrics لیارا واحد CPU/RAM را تضمین نمی‌کند. دادهٔ بدون واحد برای
نمودار یا توضیح خام قابل مشاهده است، اما به درصد ساختگی یا اثبات سلامت تبدیل
نمی‌شود. محدودیت در گزارش و وضعیت `unknown` باقی می‌ماند.

## فرمان‌های اپراتور

از ریشهٔ مخزن و محیط نصب‌شده:

```powershell
python -m lyara doctor --production --json
python -m lyara hosting
python -m lyara controls
python -m lyara emergency --enable
python -m lyara emergency --disable
python -m lyara manage YOUR_APP --enable
python -m lyara github https://github.com/OWNER/REPOSITORY
python -m lyara handoff RUN_ID --format markdown
```

برداشتن توقف و دادن دسترسی مدیریت در CLI، ترمینال تعاملی و متن تأیید دقیق نسل
جاری را می‌خواهند. MCP ابزار تأیید، برداشتن توقف یا اعطای دسترسی ندارد؛ پیشنهاد
آن هم از همان کنترل هسته می‌گذرد. در وب، کنترل‌ها احراز هویت، Origin/Host و نسل
مجوز را بررسی می‌کنند. توقف پشت صف عملیات مدل منتظر نمی‌ماند.

## اعتبارسنجی

آزمون‌های جدید شامل قیمت و شبکهٔ نامعلوم، خطای ارتباط و 429، FIFO و مهلت پاسخ مدل،
سورس GitHub ثابت، traversal و حدود ZIP، وضعیت قدیمی و ناقص، نسخهٔ اشتباه، 4xx،
GET دارای تغییر داده، توقف وسط آپلود، عدم ارسال release بعدی، محدودهٔ فقط خواندنی،
حفظ نتیجهٔ واقعی اقدام و بی‌اعتباری تأیید پس از برداشتن توقف هستند.

مجموعهٔ ۲۸۴ تست Python و تست Node رابط گذشتند. فقط یک سناریوی ساده و یک سخت
با BoxAPI/Luna اجرا شد؛ هر دو گذشتند. تلاش اول سناریوی ساده با خطای ارتباط روبه‌رو
شد و در همان ارائه‌دهنده دوباره اجرا شد؛ این تلاش و هزینهٔ نامعلومش هم ثبت شد.
سناریوی سخت HTTP 500 واقعی fixture را به 200 تبدیل کرد و خروجی ورودی‌های عادی را
حفظ کرد. API ابری در هر دو سناریو شبیه‌سازی بود. خلاصه در
[completion-v2-verification.json](completion-v2-verification.json) است.

در مرورگر، دریافت سورس با transport جداگانهٔ آزمون، فرم خصوصی، انتخاب میزبانی،
طرح کوتاه، توقف، عدم زنده‌شدن تأیید قبلی و کپی/دانلود تحویل بررسی شدند. هیچ دادهٔ
این محیط وارد رابط اصلی نمی‌شود. کد کاربر روی سرور دستیار اجرا نشد.

## نیاز واقعی به تنظیم حساب

برای استقرار خود دستیار، همان برنامهٔ Docker، دیسک پایدار کامل `/data`، یک نمونهٔ
فعال، HTTPS، `LYARA_ACCESS_TOKEN` و `LYARA_PUBLIC_HOST` لازم‌اند. برای مدیریت سایت‌ها
`LIARA_API_TOKEN` و در صورت لزوم `LIARA_TEAM_ID` باید دسترسی خواندن کاتالوگ، شبکه،
موجودی، release و لاگ ساخت و دسترسی لازم برای اقدام تأییدشده داشته باشند. کلید
BoxAPI متعلق به خود دستیار است؛ کلید و اتصال دیتابیس سایت از فرم صاحب سایت گرفته
می‌شوند. کاتالوگ دستی فقط مسیر جایگزین مشخص اپراتور است.

هیچ خرید، ساخت شبکه، انتشار یا تغییر حساب زندهٔ لیارا در این مرحله انجام نشده است.
اعتبار کلیدها، شرایط مالی نهایی، ظرفیت واقعی و عملکرد در حساب مشخص به تنظیم و
مشاهدهٔ همان حساب نیاز دارند؛ موفقیت محلی و عبور تست جای این شواهد را نمی‌گیرد.
