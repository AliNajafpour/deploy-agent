# فرمان‌ها را کجا اجرا کنیم؟

فرمان‌های رسمی `liara` را در PowerShell یا Terminal کامپیوتر توسعه اجرا کن. برای استقرار همین مخزن، ابتدا به ریشهٔ پروژه برو؛ همان پوشه‌ای که `Dockerfile`، `liara.json` و `pyproject.toml` دارد. کادر گفت‌وگوی وب Lyara محل اجرای فرمان نیست. داخل کانتینر میزبانی‌شده هم نصب Liara CLI لازم نیست؛ دستیار برای انتشار سایت‌ها مستقیماً API لیارا را صدا می‌زند.

دو CLI متفاوت داریم:

| فرمان | کارش چیست؟ | محل اجرا |
| --- | --- | --- |
| `liara …` | ابزار رسمی لیارا برای ورود، مشاهدهٔ پلن‌ها و استقرار خود دستیار | PowerShell سیستم توسعه |
| `python -m lyara …` | ابزار همین مخزن برای بررسی تنظیمات، اجرای وب و کار با دستیار | محیط Python پروژه، در ریشهٔ مخزن |

## بررسی تنظیمات بدون اتصال به حساب

در PowerShell، از ریشهٔ مخزن، محیط نصب‌شدهٔ پروژه را فعال کن و بررسی را اجرا کن:

```powershell
.\.venv\Scripts\Activate.ps1
python -m lyara doctor
python -m lyara doctor --production
python -m lyara doctor --production --json
```

اگر اجرای اسکریپت فعال‌سازی در PowerShell بسته است، می‌توانی مستقیماً از Python همان محیط استفاده کنی:

```powershell
.\.venv\Scripts\python.exe -m lyara doctor --production --json
```

برای محیط تازه، راه‌اندازی وابستگی‌ها در [README](../README.md) آمده است. `doctor` قبل از ساخت دستیار اجرا می‌شود. به مدل، ورود CLI یا حساب لیارا وصل نمی‌شود و فایل وضعیت، کلید یا پوشهٔ جدید نمی‌سازد. مقدار کلیدها، توکن‌ها و نشانی‌های واردشده را در خروجی نمایش نمی‌دهد.

این بررسی نسخهٔ Python، وجود Node برای بررسی نحو اصلاحات JavaScript، تنظیمات ارائه‌دهندهٔ مدل، کلید API، توکن لیارا، مسیرها، مجوزهای فایل و کلید رمزگذاری اطلاعات ذخیره‌شده را می‌سنجد. برای `codex` و `claude` فقط وجود فایل اجرایی بررسی می‌شود؛ فرمان اجرا نمی‌شود و ورود حساب تأیید نمی‌شود.

گزینهٔ `--production` توکن تصادفی حداقل ۳۲ نویسه‌ای برای `LYARA_ACCESS_TOKEN` و hostname عمومی برای `LYARA_PUBLIC_HOST` می‌خواهد. برای نمونه، `your-app.liara.run` درست است؛ `https://your-app.liara.run/` درست نیست. بررسی آفلاین نمی‌تواند تصادفی بودن توکن، اعتبار کلیدها، دسترسی مدل، DNS، TLS یا mount واقعی دیسک را ثابت کند.

`ready: true` یعنی خطای محلی شناخته‌شده‌ای پیدا نشده است. هشدارها را هم بخوان. خالی بودن `LYARA_HOSTING_OPTIONS=[]` فقط نبود مسیر جایگزین دستی را هشدار می‌دهد؛ در صورت دسترسی، کاتالوگ زنده استفاده می‌شود. گزینه‌های غیرخالی باید شناسهٔ یکتا، عنوان و هزینه داشته باشند. واقعی بودن پلن، قیمت و شرایط فعلی را اپراتور در لیارا بررسی می‌کند.

تنظیمات از همان مسیر پیش‌فرض اجرای دستیار خوانده می‌شوند: `.env` کنار بستهٔ پروژه، و در نبود آن `.env` پوشهٔ جاری. `LYARA_ENV_FILE` این مسیر را عوض می‌کند. متغیرهای محیطی از مقدارهای فایل اولویت بیشتری دارند. برای جلوگیری از خواندن ناخواستهٔ متغیرهای دیگر، `doctor` جای‌گذاری `${NAME}` در فایل env را انجام نمی‌دهد؛ مقدار واقعی تنظیمات را وارد کن.

پوشهٔ workspace باید وجود داشته باشد و نباید خود پوشهٔ داده یا داخل آن باشد. برای میزبانی، تمام `LYARA_DATA_DIR` باید روی دیسک پایدار بماند، شامل SQLiteها، آپلودها و `inputs.key`. اگر اطلاعات خصوصی ذخیره شده ولی کلید گم شده یا ناسازگار است، همان کلید اصلی را همراه دیتابیس بازیابی کن. ساختن کلید تازه اطلاعات قبلی را بازیابی نمی‌کند. بررسی مجوز نوشتن فقط مجوزهای سیستم‌عامل را می‌خواند؛ ظرفیت دیسک یا امکان نوشتن واقعی را با ساخت فایل آزمایش نمی‌کند.

## استقرار با CLI رسمی لیارا

این بخش را فقط اگر مسیر CLI را انتخاب کرده‌ای اجرا کن. در PowerShell سیستم توسعه:

```powershell
npm install -g @liara/cli
liara login
liara plan:list
```

فرمان نصب فقط ابزار رسمی را روی سیستم توسعه نصب می‌کند. `liara login` ورود تعاملی است؛ کلید API را داخل فرمان، کد یا کادر گفت‌وگو ننویس. شناسهٔ پلن و قیمت و شرایط فعلی را در پنل بررسی کن. [مرجع رسمی CLI](https://github.com/liara-cloud/cli/blob/master/README.md)، [فهرست پلن‌ها](https://docs.liara.ir/references/cli/see-platform-plans/)

پس از ساخت برنامهٔ Docker، ساخت دیسک `data` و ثبت متغیرهای محیطی در کنسول لیارا، از ریشهٔ مخزن اجرا کن. مقدار نمونه را با شناسهٔ برنامهٔ خودت عوض کن:

```powershell
liara deploy --app YOUR_LYARA_APP_ID --platform docker
```

برای حساب تیمی، شناسهٔ تیم را هم در همان فرمان بده:

```powershell
liara deploy --app YOUR_LYARA_APP_ID --platform docker --team-id YOUR_TEAM_ID
```

این فرمان استقرار واقعی انجام می‌دهد. راهنمای [استقرار CLI](https://docs.liara.ir/references/cli/deploy-app/) و جزئیات دیسک و تنظیمات در [راهنمای میزبانی Lyara](liara-hosting-research.md) آمده است.

## مسیر GitHub بدون CLI

اگر استقرار از GitHub را انتخاب کرده‌ای، نصب `liara` و اجرای فرمان‌های بالا لازم نیست. در کنسول لیارا، برنامهٔ Docker، دیسک و متغیرها را آماده کن؛ سپس در «استقرار جدید ← گیت‌هاب» مخزن و شاخهٔ موردنظر را انتخاب و استقرار دستی را اجرا کن. فایل آمادهٔ `liara.json` این مخزن برای این مسیر، `app` و `platform` ندارد. مقدارهای تنظیمات را در پنل قرار بده و `.env` سیستم توسعه را همراه پروژه نفرست. [راهنمای رسمی Docker و GitHub](https://docs.liara.ir/paas/docker/how-tos/deploy-app/)

فرمان‌های بالا راهنمای اجرای اپراتور هستند؛ هنگام تهیهٔ این راهنما هیچ نصب سراسری، ورود به حساب یا استقرار زنده انجام نشده است.
