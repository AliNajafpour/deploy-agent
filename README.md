# Lyara | دستیار انتشار و نگهداری لیارا

Lyara درخواست کاربر و وضعیت پروژه را بررسی می‌کند، برای انتشار یا اصلاح سرویس
طرح می‌دهد و پس از تأیید انسان، عملیات را اجرا و نتیجه را بررسی می‌کند.
رابط وب فارسی، CLI و MCP از یک هستهٔ مشترک استفاده می‌کنند.
مدل پیش‌فرض **Luna از BoxAPI** است؛ اتصال به Codex و Claude Code نیز پشتیبانی می‌شود.

## امکانات

- بررسی پروژه و ساخت بستهٔ ثابت سورس با فهرست فایل‌ها و SHA-256.
- ایجاد برنامه، آپلود سورس، ساخت release و بررسی همان نسخه و سلامت HTTP.
- دریافت لاگ، رویداد، وضعیت نسخه‌ها و دادهٔ مصرف منابع، همراه با اعلام نبود داده.
- مدیریت متغیرهای محیطی، ری‌استارت، روشن/خاموش‌کردن، پلن، دامنه، DNS و SSL.
- توقف برای تأیید طرح، ادامه پس از قطع اجرا و ثبت اقدامات برای جلوگیری از تکرار نوشتن.
- پاسخ به سؤال‌های ایجنت با حفظ درخواست قبلی و تأیید مستقل طرح جدید.
- اصلاح موانع انتشار در فایل‌های تنظیمات و شروع بک‌اند، با نمایش diff پیش از تأیید.
- گزارش JSON/Markdown از شواهد، تأیید، اقدامات و بررسی نتیجه.

## استفاده برای صاحب سایت

در رابط وب، پوشهٔ کد سایت را انتخاب کنید و به زبان معمول بگویید چه می‌خواهید.
دستیار فایل‌های شروع را بررسی می‌کند و تنظیمات اجرا، از جمله نوع برنامه و پورت،
را خودش در طرح قرار می‌دهد. دانستن این تنظیمات برای استفاده از رابط لازم نیست.
آدرس اختصاصی اختیاری است؛ جزئیات فنی و شواهد در بخش بستهٔ «جزئیات بررسی» قرار دارند.
پیش از خرید یا تغییر، اثر کار و موارد نیازمند توجه نمایش داده می‌شوند و تأیید شما لازم است.

اگر سایت به کلید یک سرویس یا اتصال دیتابیس نیاز داشته باشد، دستیار نام اطلاعات
لازم را از نمونهٔ تنظیمات و کد تشخیص می‌دهد. فایل‌های واقعی `.env`، `.env.local` و
`.env.production` پروژه، در صورت وجود، روی سرور خوانده می‌شوند؛ نمونهٔ env فقط
برای تشخیص نام‌هاست و مقدار نمونه به‌عنوان کلید واقعی استفاده نمی‌شود. مقدارهای
کم‌شده از فرم داخل برنامه گرفته می‌شوند؛ کاربر فایل env را ویرایش نمی‌کند.
تنظیمات دارای پیش‌فرض قابل استفاده دوباره پرسیده نمی‌شوند.

مقدارها وارد گفت‌وگوی مدل، گزارش یا بستهٔ سورس نمی‌شوند. اعمالشان روی سایت بخشی
از طرح تأییدشده و قبل از ساخت نسخه است. ذخیرهٔ محلی با Fernet رمز می‌شود؛
`inputs.sqlite` و `inputs.key` در پوشهٔ دادهٔ خصوصی قرار دارند. دسترسی و نسخهٔ
پشتیبان این پوشه باید محافظت شوند؛ حذف فایل کلید، اطلاعات ذخیره‌شده را غیرقابل
بازیابی می‌کند. اتصال دیتابیس موجود دریافت می‌شود؛ ساخت خودکار دیتابیس ابری جزو
این مسیر نیست. ورودی‌های عمومیِ برنامه‌های سمت مرورگر می‌توانند در کد خروجی آن
برنامه منتشر شوند؛ کلید خصوصی سرویس را در این متغیرها قرار ندهید.

راه‌انداز برنامه کلیدها و دسترسی‌های سرور را در `.env` تنظیم می‌کند. برای ایجاد سایت
جدید در حساب واقعی، گزینه‌های میزبانی را همراه هزینه و شرایط فعلی در
`LYARA_HOSTING_OPTIONS` وارد کند؛ برای مثال:

```dotenv
LYARA_HOSTING_OPTIONS=[{"id":"PLAN_ID_FROM_HOST","title":"سایت کوچک","cost":"قیمت و شرایط فعلی این گزینه"}]
```

کاربر عنوان و هزینه را انتخاب می‌کند؛ شناسهٔ داخلی را وارد نمی‌کند. این فهرست را
راه‌انداز باید به‌روز نگه دارد؛ برنامه قیمت زنده دریافت نمی‌کند. تا زمانی که گزینه‌ای
تنظیم نشده باشد، رابط برای سایت جدید گزینهٔ خریدی پیشنهاد نمی‌دهد. آزمایشگاه محلی
گزینهٔ رایگان آزمایشی خودش را دارد.

## نصب

به Python 3.11 یا جدیدتر نیاز دارید. برای اجرای نمونه‌ها و بررسی نحو فایل‌های
Node.js، نصب Node.js نیز لازم است.

```sh
git clone https://github.com/AliNajafpour/deploy-agent.git
cd deploy-agent
python -m venv .venv
```

در Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -e .
Copy-Item .env.example .env
```

در Linux یا macOS:

```sh
.venv/bin/python -m pip install -e .
cp .env.example .env
```

دستورهای بعدی برای PowerShell نوشته شده‌اند. در Linux و macOS به‌جای
`.\.venv\Scripts\python.exe` از `.venv/bin/python` استفاده کنید.

## تنظیم مدل BoxAPI

کلید BoxAPI را در `.env` وارد کنید:

```dotenv
LYARA_PROVIDER=api
LYARA_LLM_BASE_URL=https://ai.boxapi.ir/ai/v1
LYARA_MODEL=openai/gpt-6-luna
LYARA_LLM_API_KEY=YOUR_BOXAPI_KEY
```

آدرس پایه و مدل پیش‌فرض برنامه همین مقادیر هستند. برای استفاده از یک سرویس
سازگار دیگر، `LYARA_LLM_BASE_URL` و `LYARA_MODEL` را تغییر دهید. سرویس باید
Chat Completions و `response_format: json_object` را پشتیبانی کند.
[مستندات BoxAPI](https://boxapi.ir/docs/ai/).

کلید فقط روی سرور خوانده می‌شود؛ آن را در پیام کاربر، سورس پروژه یا Git قرار ندهید.
کلید مدل با توکن سرویس استقرار لیارا مستقل است.

## دموی بدون کلید

```powershell
.\.venv\Scripts\python.exe -m lyara --demo serve --port 8791
```

رابط در `http://127.0.0.1:8791` در دسترس است. در این حالت، مدل و پاسخ‌های ابری
شبیه‌سازی می‌شوند و هیچ حساب ابری تغییر نمی‌کند. پروژهٔ نمونه در
`examples/hello-node` قرار دارد.

برای اجرای واقعی برنامه‌های آزمایشی با API ابری شبیه‌سازی‌شده:

```powershell
.\.venv\Scripts\python.exe -m tests.lab --serve --provider scripted --fixture 01-static --port 8793
```

این آزمایشگاه از planner ثابت استفاده می‌کند. برای آزمون با مدل واقعی،
[راهنمای پروژه‌های آزمایشی](tests/projects/README.md) را ببینید.

## اتصال به سرویس استقرار

برای استفاده از APIهای لیارا، تنظیمات زیر را نیز در `.env` قرار دهید:

```dotenv
LIARA_API_TOKEN=YOUR_LIARA_TOKEN
LIARA_TEAM_ID=
LYARA_WORKSPACE=.
LYARA_DATA_DIR=.lyara
```

`LYARA_WORKSPACE` ریشهٔ مجاز پروژه‌ها و `LYARA_DATA_DIR` محل نگهداری وضعیت،
تأییدها و بسته‌های سورس است. مسیرهای نسبی نسبت به محل فایل `.env` تفسیر می‌شوند.
برای انتخاب فایل تنظیمات دیگر، `LYARA_ENV_FILE` را تنظیم کنید.

```powershell
.\.venv\Scripts\python.exe -m lyara serve --port 8792
```

رابط در `http://127.0.0.1:8792` در دسترس است. نام برنامه، پوشهٔ سورس و پورت را
مشخص کنید؛ ایجاد برنامهٔ جدید به شناسهٔ پلن انتخابی نیز نیاز دارد. قیمت یا شناسهٔ
پلن حدس زده نمی‌شود. پیش از هر تغییر، طرح و پیامدهای آن برای تأیید نمایش داده می‌شوند.

نمونه‌های CLI:

```powershell
.\.venv\Scripts\python.exe -m lyara deploy my-app --source examples/hello-node --plan-id PLAN_ID --port 3000
.\.venv\Scripts\python.exe -m lyara approve RUN_ID
.\.venv\Scripts\python.exe -m lyara status RUN_ID
.\.venv\Scripts\python.exe -m lyara answer RUN_ID --message "پورت 3000" --port 3000
.\.venv\Scripts\python.exe -m lyara resume RUN_ID
.\.venv\Scripts\python.exe -m lyara recheck RUN_ID
.\.venv\Scripts\python.exe -m lyara recovery RUN_ID
.\.venv\Scripts\python.exe -m lyara report RUN_ID --format markdown
.\.venv\Scripts\python.exe -m lyara diagnose my-app --message "سایتم خطای ۵۰۰ می‌دهد"
.\.venv\Scripts\python.exe -m lyara repair my-app --source examples/hello-node --port 3000
.\.venv\Scripts\python.exe -m lyara monitor my-app --interval 60
```

تأیید CLI به ترمینال تعاملی و واردکردن ابتدای digest طرح نیاز دارد. پایش CLI
فقط اطلاعات را می‌خواند و تغییری را خودکار اجرا نمی‌کند.

## اصلاح موانع انتشار

در حالت «رفع مانع انتشار»، ایجنت می‌تواند فرمان شروع، پورت یا bind، نحو فایل
شروع بک‌اند و وابستگی جاافتاده در manifest را اصلاح کند. فایل‌ها در یک بستهٔ
جدا آماده می‌شوند؛ diff و بررسی ساختاری پیش از تأیید نمایش داده می‌شوند.
پس از تأیید، همان بسته منتشر و نتیجه بررسی می‌شود.

سورس اصلی تغییر نمی‌کند؛ انتشار بعدی از سورس اصلی، اصلاح قبلی را خودکار ندارد.
نصب وابستگی در محیط ساخت نسخه انجام می‌شود. تغییر قابلیت سایت، رابط کاربری،
منطق کسب‌وکار و داده‌ها در این مسیر مجاز نیست. تغییر وابستگی همراه lockfile
فعلاً به بازتولید معتبر فایل قفل با ابزار مدیریت پکیج نیاز دارد.
[جزئیات اصلاح انتشار](docs/deployment-repair.md).

## استفاده از Codex یا Claude Code

برای استفاده از ورود موجود CLI به‌جای BoxAPI، یکی از این providerها را انتخاب کنید:

```dotenv
LYARA_PROVIDER=codex
# یا: LYARA_PROVIDER=claude
LYARA_MODEL=
```

CLI انتخاب‌شده باید نصب و وارد حساب شده باشد. با خالی‌گذاشتن `LYARA_MODEL`،
مدل پیش‌فرض همان CLI استفاده می‌شود. Lyara آن را در پوشهٔ موقت و بدون ابزار
اجرایی یا کلید زیرساخت فراخوانی می‌کند. برای مسیر اجرایی سفارشی،
`LYARA_CODEX_BIN` یا `LYARA_CLAUDE_BIN` را تنظیم کنید.

برای اتصال ابزارهای Lyara از طریق MCP، نمونهٔ ثبت سرور در PowerShell:

```powershell
$pythonPath = (Resolve-Path .\.venv\Scripts\python.exe).Path
codex mcp add lyara -- $pythonPath -m lyara mcp
claude mcp add --transport stdio lyara -- $pythonPath -m lyara mcp
```

در Linux و macOS مسیر مطلق `.venv/bin/python` را به فرمان میزبان بدهید.
نصب editable و فایل `.env` پروژه اجازه می‌دهند سرور از پوشه‌های دیگر نیز اجرا شود.
وب و MCP باید به همان `LYARA_DATA_DIR` اشاره کنند تا طرح و تأیید مشترک بماند.
MCP از مدل میزبان استفاده می‌کند و به کلید LLM داخلی نیاز ندارد.

ابزارهای MCP شامل بررسی سورس، خواندن شواهد، دامنه و DNS، ساخت پیشنهاد، وضعیت،
گزارش و بررسی دوبارهٔ نتیجه هستند. ابتدا `proposal_schema` را بخوانید.
`propose` فقط طرح را ثبت می‌کند؛ تأیید در رابط یا ترمینال انسان انجام می‌شود.

## معماری

```text
Persian web / CLI / MCP
          |
   shared Assistant service
          |
 inspect -> observe -> plan -> human approval -> execute -> verify
                       |                       |
             BoxAPI / Codex / Claude      Liara HTTP API
          |
 SQLite checkpoints + action journal
```

LangGraph جریان کار و توقف برای تأیید را هماهنگ می‌کند. SQLite وضعیت و دفتر
اقدامات را نگه می‌دارد. APIهای PaaS از `https://api.liara.ir` و DNS از
`https://dns-service.liara.ir` فراخوانی می‌شوند؛ احراز هویت با Bearer token است.
در صورت تنظیم `LIARA_TEAM_ID`، پارامتر `teamID` نیز ارسال می‌شود.
قراردادهای API در [docs/reference](docs/reference/README.md) قرار دارند.

## امنیت و محدودیت‌ها

- تأیید به برنامه، پارامترهای طرح و هش بستهٔ سورس متصل است. طرح عوض‌شده تأیید تازه می‌خواهد.
- فایل‌های env، کلیدها، وابستگی‌ها، VCS و symlinkها از بستهٔ سورس حذف می‌شوند؛
  تشخیص همهٔ انواع اطلاعات محرمانه در فایل دلخواه تضمین نمی‌شود.
- مقادیر محرمانهٔ استقرار با ارجاع‌های `LYARA_DEPLOY_*` خوانده می‌شوند و وارد مدل نمی‌شوند.
- نتیجهٔ نامشخص عملیات نوشتنی خودکار تکرار نمی‌شود. checkpoint تراکنش ابری را اتمی نمی‌کند.
- بازگشت فقط سورس قبلی را با تأیید تازه منتشر می‌کند؛ داده، env، پلن و DNS را برنمی‌گرداند.
- پذیرش درخواست ری‌استارت، SSL یا DNS به‌تنهایی اثبات اثر نهایی نیست؛ محدودیت بررسی نمایش داده می‌شود.
- تغییر nameserver در ثبت‌کننده ممکن است دستی باشد. نبود دادهٔ منابع به معنی سلامت نیست.
- اجرای عمومی به `LYARA_ACCESS_TOKEN`، `LYARA_PUBLIC_HOST`، HTTPS و کنترل دسترسی نیاز دارد.
  این نسخه برای یک اپراتور طراحی شده است.
- شواهد آزمون‌های ارائه‌شده از اجرای محلی و API ابری شبیه‌سازی‌شده به دست آمده‌اند؛
  سازگاری با حساب زندهٔ لیارا ادعا نمی‌شود.

## آزمون‌ها

برای دو سناریوی انتشار استاتیک و اصلاح وابستگی، پس از تنظیم BoxAPI:

```powershell
.\.venv\Scripts\python.exe -m tests.agent_projects --provider api --case 01-static
.\.venv\Scripts\python.exe -m tests.repair_agent --provider api --fixture 02-missing-package
```

سناریوی نصب وابستگی به wheel محلی یا کش موجود uv نیاز دارد و دانلود شبکه انجام
نمی‌دهد. [گزارش دو سناریو با Luna](docs/boxapi-verification.json)،
[پروژه‌های آزمایشی](tests/projects/README.md) و
[نمونه‌های اصلاح انتشار](tests/repair_projects/README.md) را ببینید.

آزمون‌های خودکار بدون فراخوانی مدل خارجی:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

[معماری تفصیلی](docs/design.md)، [تحقیق نمونه‌های مشابه](docs/research-global.md)
و [سناریوی دموی پنج‌دقیقه‌ای](docs/demo-script.md) نیز در مستندات قرار دارند.
